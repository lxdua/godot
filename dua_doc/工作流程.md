
# Godot 引擎魔改工作流程

> 本文档记录使用 AI 辅助修改 Godot 引擎源码的标准流程，供后续参考。

---

## 一、魔改功能的完整流程

### 第 1 步：选择改动方向

1. 让 AI 分析 Godot 某个系统的整体架构
2. 列出各模块的现状和可改进方向
3. 按**实用性 × 难度 × 影响范围**排优先级
4. 选定一个方向

### 第 2 步：深入分析现有代码

1. 完整阅读目标文件的 `.h` 和 `.cpp`
2. 梳理当前的代码架构、输入路径、状态机
3. 找出**具体哪些地方**需要改、每处的现状是什么
4. 与相关模块对比（如 TextEdit 已有平滑滚动，ScrollContainer 没有）

### 第 3 步：确认设计决策

在动手写代码前，明确以下关键决策（通过与用户讨论确定）：

- **作用范围**：哪些输入路径需要覆盖
- **算法选型**：如指数衰减 vs 线性减速
- **默认行为**：新功能默认开启还是关闭
- **属性设计**：暴露哪些参数、默认值、取值范围

### 第 4 步：实施代码修改

按以下顺序改动：

1. **`.h` 文件**：新增属性、状态变量、方法声明
2. **`.cpp` 文件**：
   - 新增核心方法（如 `_smooth_scroll_towards`、`_animate_smooth_scroll`）
   - 修改各输入路径（鼠标滚轮、Pan 手势、API 等）
   - 修改 `_notification()` 中的帧处理逻辑
   - 新增 getter/setter
   - 在 `_bind_methods()` 中注册方法和属性（`ClassDB::bind_method`、`ADD_GROUP`、`ADD_PROPERTY`）
3. **验证括号匹配**：修改完后检查 `{` 和 `}` 数量是否一致

### 第 5 步：添加文档

1. **编辑器悬浮提示（英文）**：修改 `doc/classes/<ClassName>.xml`，在 `<members>` 中添加新属性的 `<member>` 节点，包含英文说明
2. **中文说明**：由于 Godot 翻译由 Weblate 平台管理（`.po` 文件），不直接修改翻译文件。在 `dua_doc/` 下的改动记录文档中写中文属性说明表

### 第 6 步：编写改动记录文档

在 `dua_doc/` 目录下创建 Markdown 文档，包含：

| 章节 | 内容 |
|------|------|
| 修改目的 | 为什么要改，原版有什么问题 |
| 改动文件清单 | 哪些文件被修改了，每个文件改了什么 |
| 新增属性 | 属性名、类型、默认值、范围、说明 |
| 属性中文说明 | 中文翻译表（编辑器暂无中文提示时参考） |
| 具体修改详解 | 每处改动的位置、原版代码、改后代码、含义 |
| 算法原理 | 涉及的数学/物理原理（如指数衰减公式） |
| 状态机总览 | 整体流程图 |
| 参数调节指南 | 用户调参的直觉指南 |

## 三、项目目录约定

```
godot/
├── dua_doc/                          ← 魔改文档目录，随代码一起提交
│   ├── 工作流程.md                    ← 本文件
│   ├── ScrollContainer平滑滚动.md     ← UI 控件改动记录
│   └── Camera2D相机震动.md            ← Camera2D 震动系统改动记录
├── scene/gui/                        ← UI 控件源码
├── scene/2d/                         ← 2D 场景节点源码
├── doc/classes/                      ← 编辑器文档 XML（悬浮提示）
└── editor/translations/              ← 翻译文件（一般不直接修改）
```

## 五、AI 辅助注意事项

1. **让 AI 先读代码再改**：修改前务必让 AI 完整阅读目标文件的 `.h` 和 `.cpp`，避免基于猜测改错
2. **分步确认设计决策**：不要让 AI 一次性做完所有决策，关键选择点（作用范围、算法、默认值）需要逐个确认
3. **改完检查括号**：C++ 代码改完后让 AI 验证 `{` `}` 数量匹配
4. **文档同步**：每次改动都要同步更新 `doc/classes/` 的 XML 文档和 `dua_doc/` 的改动记录
5. **不要直接改翻译文件**：`.po` 翻译文件由自动化流程管理，中文说明写到 `dua_doc/` 文档中即可
