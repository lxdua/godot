# Container 布局态动画（Layout Transition / FLIP） · 开发文档

> 目标：当 `Container` 家族（`BoxContainer`、`GridContainer`、`FlowContainer`、`VirtualBoxContainer` 等）的子节点集合或尺寸发生变化时，**自动**应用平滑过渡动画，替代当前的"瞬间跳位置"表现。
> 状态：设计草案 v0.1
> 归属：扩展 `scene/gui/container.cpp/h`；新增 `scene/gui/container_transition.cpp/h`

---

## 1. 背景

### 1.1 问题陈述

当前 Godot 的 `Container` 家族在子节点集合变化时**只有布局、没有动画**：

- `add_child` / `remove_child` / `move_child` 触发 `NOTIFICATION_SORT_CHILDREN`
- 排版瞬间生效，所有兄弟节点"啪"地跳到新位置
- 若要平滑过渡，用户必须：
  1. 改动前手动记录每个子节点位置
  2. 改动后等一帧让布局生效
  3. 手动对每个子节点 tween `position`
  4. 处理"被删节点不能立刻 `free`，动画期间要保留"的边界
  5. 处理"动画中途又来一次变更"的中断重算

每个项目都在重写这段代码，错误率极高（尤其是第 4、5 步），也是 Godot UI 观感普遍被吐槽"生硬"的主因之一。

### 1.2 五层观感需求

"布局变化"其实包含五个独立维度，现状全部为空：

| 层次 | 触发 | 观感期望 | 典型场景 |
|---|---|---|---|
| **L1 位移** | 兄弟节点位置因插删变化 | 从旧位置平滑滑到新位置 | 任意容器插删 |
| **L2 入场** | 新子节点加入 | 淡入 / 滑入 / 缩放展开 | 聊天新消息、背包新物品 |
| **L3 离场** | 子节点被移除 | 淡出 / 滑出 / 缩小消失 | 物品使用、删除好友 |
| **L4 自适应** | 某子节点自身尺寸变了 | 容器尺寸平滑跟随、兄弟节点平滑推开 | 展开详情、评论展开 |
| **L5 跨容器** | 同一节点从容器 A 移到容器 B | 节点视觉上"飞"过去 | 拖拽排序、Hero 过渡 |

**L5 不在本提案范围**——它涉及全局 Overlay 与场景树层级协调，量级和单容器动画不同，作为独立特性（路线图 §6.1 共享元素）另行推进。

**L4 不单独建类**——只要 L1 机制到位，子节点 size 变化会触发 Container 重排，L1 FLIP 自然覆盖兄弟节点的位移。Flutter 之所以单独分出 `AnimatedSize` 是其 Widget 组合模型决定的，Godot 的 `Container` 模型天然包含 L4。

本文档聚焦 **L1 ~ L4**。

### 1.3 现状替代品的局限

| 方案 | 覆盖 | 局限 |
|---|---|---|
| 用户手动 `Tween` | L1 / L2 / L3 | 重复造、易错，离场 free 冲突普遍被踩坑 |
| `AnimationPlayer` 关键帧 | L1 / L2 | 只适合固定子节点数量的已知场景 |
| 社区 addon（屈指可数） | 部分 L1 | 覆盖面残缺，中断重算、reduce motion、虚拟化列表协作基本没有 |

### 1.4 目标

在 `Container` 基类上提供**开箱即用的布局过渡机制**，做到：

1. **一个 export 属性即启用**（对位 Android `android:animateLayoutChanges`），90% 用户零代码获得合理默认动画
2. **信号钩子可定制**入场 / 离场 / 位移三类动画
3. **`ContainerTransition` 资源可复用**，统一项目风格
4. **与 `Container` 家族全员兼容**：`BoxContainer` / `GridContainer` / `FlowContainer` / `VirtualBoxContainer` 共用同一机制
5. **基于 FLIP**：只动 `transform`、不动 `position`，保证布局正确性和可中断性
6. **尊重系统无障碍偏好**：`reduce motion` 模式下自动退化为瞬切

### 1.5 非目标

- 不新造动画系统，复用 `Tween` / `AnimationPlayer`
- 不做 L5 跨容器共享元素
- 不做状态机式过渡（对位 Android `MotionLayout`）——作为后续可选扩展
- 不自动为非 `Container` 的自定义控件布局系统生效（用户自写的 `custom_minimum_size` 动态 Control 不在默认范围内）

## 2. 设计原则

1. **零侵入开关**：`animate_layout_changes = true` 一个 flag 获得默认行为，不强迫用户理解 FLIP
2. **分层 API**：开关（L0）→ 信号（L1）→ 资源（L2），按需求深度逐级进阶，互不干扰
3. **FLIP 不可妥协**：只操作 `transform`，不污染 `position` / `size`，保证布局计算始终基于真值
4. **离场生命周期引擎托管**：用户调 `queue_free()` 就行，引擎自己处理"动画期间延后 free"
5. **可中断、可重入**：任何时刻的新变更都以"当前视觉位置"为 First，重新 invert + play
6. **无障碍一等公民**：系统 reduce motion 或项目设置禁用时，所有动画立即降级为瞬切

---

## 3. 架构总览

### 3.1 FLIP 偏移载体：`Control::_layout_transition_offset`

FLIP 的核心前提是"有一个**纯视觉偏移**通道，它不污染布局计算"。Godot 的 `Control` 当前**没有**这样的字段：

| 候选 | 问题 |
|---|---|
| 直接 tween `position` | `position` 是布局真值的一部分，容器 `_sort_children` 会立即覆盖；而且 `get_rect()` 也会变，引起用户代码歧义 |
| 借用 `pivot_offset` | `pivot_offset` 是旋转 / 缩放的参考点，不是平移 |
| 借用 `scale` / `rotation` | 语义不符，且会缩放 hit-test |
| 直接改 `CanvasItem::_canvas_item_transform`（运行时矩阵） | 每帧排版后都会被重算冲掉 |

**方案（敲定）**：在 `Control` 内部新增一个专用字段 `Vector2 _layout_transition_offset`：

```cpp
class Control : public CanvasItem {
    // ... existing fields
private:
    Vector2 _layout_transition_offset;  // 仅用于 Container FLIP 动画，不进入 get_rect()
public:
    void set_layout_transition_offset(const Vector2 &p_offset);
    Vector2 get_layout_transition_offset() const;
};
```

**语义约束**：

1. **不参与布局计算**：`get_rect()`、`get_global_rect()`、anchor / offset 的解析、`_sort_children` 分配的 rect 都**不**考虑此字段
2. **只参与绘制变换**：在 `Control::_get_internal_transform()`（或 `CanvasItem::get_canvas_transform()` 的链路上）叠加一次平移
3. **参与命中检测**：`_gui_input_event` 的点命中测试按**视觉位置**（即叠加 offset 后）判定，避免"看见的卡片点不到 / 点到空气"
4. **不可由用户直接赋值**（Editor 面板隐藏、脚本默认不导出）：它是 Container 的私有协议字段。用户想做"视觉位移"请用 `position`
5. **对 `VisualServer` / `RenderingServer` 透明**：实现上就是在构造 `Transform2D` 时加一个 translate，不需要特殊通道

**Tween 目标属性**：

```gdscript
tween.tween_property(c, "_layout_transition_offset", Vector2.ZERO, duration)
```

（属性名以 `_` 开头表示内部；如需暴露为 Tween 友好可取 `layout_transition_offset` 不带下划线，但保持"不建议用户手写"的文档约定。）

**回退方案（若引擎改动被否）**：在 `Container` 内部维护 `HashMap<Control *, Vector2> _flip_offsets`，在 `_notification(NOTIFICATION_DRAW)` 或 `_pre_sort_children` 前后手动 push/pop `CanvasItem` transform。性能与维护成本略高于在 `Control` 加字段，但 API 不变。

### 3.2 FLIP 核心机制

```
               用户触发 add/remove/move_child
                              │
                              ▼
┌─────────────────────────────────────────────────┐
│ Container.NOTIFICATION_SORT_CHILDREN 之前        │
│                                                  │
│   [First]  snapshot_rects = { child: rect, ... } │
│            对当前所有活跃子节点拍快照              │
└─────────────────────────────────────────────────┘
                              │
                              ▼
         Container 正常走 _sort_children() 排版逻辑
                              │
                              ▼
┌─────────────────────────────────────────────────┐
│ Container.NOTIFICATION_SORT_CHILDREN 之后        │
│                                                  │
│   [Last]    new_rect = child.get_rect()          │
│   [Invert]  delta = old_rect.position            │
│                       - new_rect.position        │
│             若 |delta| > ε:                      │
│               child._layout_transition_offset     │
│                 += delta                         │
│                (child 视觉上仍在 old 位置)        │
│   [Play]    Tween(child,                         │
│              "_layout_transition_offset",        │
│              Vector2.ZERO, duration)             │
└─────────────────────────────────────────────────┘
```

**关键性质**：

- `child.position` 在每一步都是**布局算出来的真值**，只有 `_layout_transition_offset` 被用作视觉偏移
- 动画结束后 `_layout_transition_offset = 0`，子节点视觉位置 = 布局位置，自然收敛
- 中断：第二次变更来时，`snapshot_rects` 重新基于"当前已被 invert 偏移过的视觉位置"采集，FLIP 自然续上

### 3.3 节点生命周期

```
新子节点：
    add_child(c)
        │
        │ SORT_CHILDREN 后
        ▼
    Container 识别 c 不在 snapshot_rects → 入场
        │
        ▼
    应用 enter_preset（FADE / SLIDE / SCALE / ...）
        │   初态：modulate.a=0 或 scale=0.8 或 position offset
        ▼
    Tween 到常态

被移除子节点：
    用户调用 c.queue_free() 或 container.remove_child(c)
        │
        ▼
    Container 拦截：把 c 从主布局流移到"退场区"（保持原 rect，从布局循环中跳过）
        │
        ▼
    应用 exit_preset（FADE / SLIDE / SCALE / ...）
        │
        ▼
    Tween 完成 → 真正 free(c)

位移子节点：
    见 §3.1 FLIP 流程
```

**退场区（exit area）实现**：在 Container 内部维护一个 `LocalVector<Control*> exiting_children`。这些节点：

- 仍然是 Container 的子节点（Godot 树里可见）
- 在 `_sort_children()` 里被跳过（不参与布局分配）
- 视觉上保留在退场动画启动时的位置
- 动画完成回调真正 `queue_free`

### 3.4 数据结构

```cpp
class Container {
    // --- 开关 ---
    bool animate_layout_changes = false;
    float layout_transition_duration = 0.2;
    Tween::TransitionType layout_transition_ease = Tween::TRANS_CUBIC;
    EnterPreset enter_preset = ENTER_FADE_SLIDE;
    ExitPreset exit_preset  = EXIT_FADE_SLIDE;
    float stagger_delay = 0.0;  // 每子节点错峰
    Ref<ContainerTransition> transition_override;  // L2 资源（可空）

    // --- 运行时 ---
    HashMap<Control *, Rect2> snapshot_rects;   // First 阶段快照
    HashMap<Control *, Ref<Tween>> active_tweens; // 每子节点当前动画（可被中断）
    LocalVector<Control *> exiting_children;    // 退场区
    bool animate_layout_changes_skip_next = false; // 一次性跳过
};

enum EnterPreset {
    ENTER_NONE,        // 无入场动画（仅 L1 位移）
    ENTER_FADE,        // modulate.a: 0 → 1
    ENTER_SLIDE,       // position offset + transform
    ENTER_SCALE,       // scale: 0.8 → 1
    ENTER_FADE_SLIDE,  // 默认：淡入 + 从反方向滑入
    ENTER_FADE_SCALE,
    ENTER_CUSTOM,      // 通过信号或 ContainerTransition 接管
};

enum ExitPreset { /* 对称 */ };
```

## 4. API 设计

### 4.1 L0：`Container` 基类属性（最低门槛）

| 属性 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `animate_layout_changes` | `bool` | `false` | 总开关；向后兼容 |
| `layout_transition_duration` | `float` | `0.2` | L1 / L2 / L3 默认时长（秒） |
| `layout_transition_ease` | `Tween.TransitionType` | `TRANS_CUBIC` | 默认缓动 |
| `enter_preset` | `EnterPreset` enum | `ENTER_FADE_SLIDE` | 入场预设 |
| `exit_preset` | `ExitPreset` enum | `EXIT_FADE_SLIDE` | 离场预设 |
| `stagger_delay` | `float` | `0.0` | 子节点之间错峰秒数 |
| `transition_override` | `ContainerTransition` | `null` | L2 资源覆盖；非空时上面所有属性被忽略 |

**典型用法**：

```gdscript
# 完全零代码：打开开关
$VBoxContainer.animate_layout_changes = true
```

### 4.2 L1：信号钩子（中等灵活度）

```gdscript
# 子节点即将入场；用户可 emit 后自己播动画，返回 Tween 让 Container 等它
signal child_entering(child: Control, tween_holder: Array)
# 约定：若需接管，把自己的 Tween 对象 append 到 tween_holder

# 子节点即将离场；用户必须调用 done 回调后 Container 才真正 free
signal child_exiting(child: Control, done: Callable)

# 批量位移即将应用；用户可 inspect 或完全接管
signal children_rearranging(moves: Array[Dictionary])
# 每条：{ "child": Control, "from_rect": Rect2, "to_rect": Rect2 }
# 接管方式：给每个 child.set_meta("_layout_transition_skip", true)，然后自播
```

**用户侧接管 exit 动画的例子**：

```gdscript
$Inventory.child_exiting.connect(func(child, done):
    var t := create_tween()
    t.tween_property(child, "scale", Vector2.ZERO, 0.3)
    t.parallel().tween_property(child, "modulate:a", 0.0, 0.3)
    t.finished.connect(done)  # 动画完成后 Container 才真 free
)
```

### 4.3 L2：`ContainerTransition` 资源（高灵活度、可复用）

```gdscript
class_name ContainerTransition extends Resource

@export var move_duration: float = 0.2
@export var move_curve: Curve
@export var enter_animation: AnimationLibrary      # 或 StringName 指向 AnimationPlayer 动画名
@export var exit_animation: AnimationLibrary
@export var stagger_delay: float = 0.0
@export var respect_reduce_motion: bool = true
```

**项目级用法**：

```gdscript
# Project 主题里定义一个全局过渡风格
var game_transition := preload("res://ui/motions/snappy.tres") as ContainerTransition

# 所有 UI 容器统一风格
for node in find_all_containers():
    node.transition_override = game_transition
```

这对标 Material Motion Tokens / Figma Variables 的动画层：用户改一处，全局观感统一变化。

### 4.4 运行时 API

```gdscript
# 播完 exit 动画后自动 queue_free 子节点（推荐路径）
container.animate_remove(child: Control) -> void
container.animate_remove(child: Control, on_done: Callable) -> void  # 完成回调，不自动 free

# 一次性跳过下一次过渡（紧急场景用，比如数据突变立即归位）
container.skip_next_layout_transition()

# 强制立刻完成所有未完成的动画（跳转场景前清理）
container.finish_layout_transitions_now()

# 查询
container.is_child_exiting(child) -> bool   # 节点是否在退场区

# 开发期辅助：直调 queue_free 时发 warning
container.strict_exit_animation = false     # 默认 false
```

## 5. 关键算法

### 5.1 FLIP 主循环

```
on Container.NOTIFICATION_PRE_SORT_CHILDREN:
    if not animate_layout_changes: return
    snapshot_rects.clear()
    for c in get_children():
        if c in exiting_children: continue
        snapshot_rects[c] = c.get_rect()

on Container.NOTIFICATION_SORT_CHILDREN:
    // 正常排版已完成
    if not animate_layout_changes: return
    if animate_layout_changes_skip_next:
        animate_layout_changes_skip_next = false
        return

    var index = 0
    for c in get_children():
        if c in exiting_children: continue

        var is_new = not snapshot_rects.has(c)
        var old_rect = snapshot_rects.get(c, c.get_rect())
        var new_rect = c.get_rect()
        var delta = old_rect.position - new_rect.position

        if is_new:
            apply_enter(c, index)
        elif delta.length_squared() > EPSILON:
            apply_move(c, delta, index)

        index += 1
```

**`NOTIFICATION_PRE_SORT_CHILDREN`** 是需要新增的通知（或用 `_notification` 的 `NOTIFICATION_SORT_CHILDREN` 前手动 hook）。Godot 目前没有 "pre-sort" 通知，实现上可能需要在 `Container::queue_sort` 调用前插一个钩子。

### 5.2 中断处理

```
apply_move(c, delta, index):
    // 若已有动画在跑，它此刻的 _layout_transition_offset 是某个非零值
    var current_visual_offset = c._layout_transition_offset
    // snapshot_rects 里记录的是"逻辑 rect"，delta 已经算对了
    // 需要做的是：让 tween 的起点 = 当前视觉偏移 + delta
    // 因为 c.position 刚刚变成 new_rect.position
    // 视觉位置 = new_rect.position + _layout_transition_offset = old_visual_position
    // 想达到的效果：_layout_transition_offset 从 (old_visual - new_rect) 平滑到 0

    var start_offset = current_visual_offset + delta
    if active_tweens.has(c):
        active_tweens[c].kill()
    c._layout_transition_offset = start_offset

    var tween = create_tween()
    tween.tween_property(c, "_layout_transition_offset", Vector2.ZERO, layout_transition_duration)
         .set_trans(layout_transition_ease)
         .set_delay(index * stagger_delay)
    active_tweens[c] = tween
```

**核心不变量**：`c.position` 始终是布局算出的正确值；视觉偏移通过 `_layout_transition_offset` 表达。动画完成后该字段归零，视觉 = 布局。

### 5.3 入场

```
apply_enter(c, index):
    match enter_preset:
        ENTER_FADE:
            c.modulate.a = 0
            tween.tween_property(c, "modulate:a", 1.0, duration)
        ENTER_SCALE:
            c.scale = Vector2(0.8, 0.8)
            tween.tween_property(c, "scale", Vector2.ONE, duration)
        ENTER_SLIDE:
            var dir = infer_enter_direction()  // 基于容器 orientation
            c._layout_transition_offset = dir * c.size.length()
            tween.tween_property(c, "_layout_transition_offset", Vector2.ZERO, duration)
        ENTER_FADE_SLIDE:
            c.modulate.a = 0
            c._layout_transition_offset = infer_enter_direction() * 20  // 小幅位移
            tween.parallel().tween_property(c, "modulate:a", 1.0, duration)
            tween.parallel().tween_property(c, "_layout_transition_offset", Vector2.ZERO, duration)
        ENTER_CUSTOM:
            emit_signal("child_entering", c, tween_holder)
```

### 5.4 离场与退场区管理

```
on remove_child(c):  // 或 queue_free 拦截
    if not animate_layout_changes:
        return _default_remove(c)
    if c.is_in_exiting():
        return  // 已经在退场中，忽略重复调用

    // 进入退场区
    exiting_children.append(c)
    c.set_meta("_exiting_rect", c.get_rect())  // 冻结位置

    // 从主布局流移除但保留在场景树
    // 实现上：_sort_children 里跳过它，不给它分配新 rect
    // 通过覆盖 c.set_notify_transform 让外部 set_rect 无效 —— 或更干净地：
    // 把 c 的 anchors/offsets 固定为当前 rect

    apply_exit(c, lambda: _finalize_free(c))

apply_exit(c, on_done):
    match exit_preset:
        EXIT_FADE:
            tween.tween_property(c, "modulate:a", 0, duration)
        ...
    tween.finished.connect(on_done)

_finalize_free(c):
    exiting_children.erase(c)
    c.queue_free()
```

**子节点在退场区时**：`get_children()` 仍然包含它（Godot 树结构不变），但 `_sort_children()` 跳过。外部代码不应假定"子节点数"等于"活跃子节点数"。暴露 `get_active_child_count()`  / `get_exiting_children()` 供用户区分。

### 5.5 Stagger

```
tween.tween_property(...).set_delay(index * stagger_delay)
```

简单有效。`index` 是当前子节点在活跃序列中的下标，不是全局 child index。

### 5.6 Reduce Motion

```
if should_skip_animation():
    // 不走 FLIP，不播 enter/exit
    if c.is_in_exiting():
        _finalize_free(c)
    return

should_skip_animation() -> bool:
    if ProjectSettings.get("gui/animations/respect_reduce_motion"):
        if DisplayServer.is_reduce_motion_enabled():
            return true
    return false
```

需要新增 `DisplayServer.is_reduce_motion_enabled()` API（跨平台查询系统偏好）。Android 从 `Settings.Global.ANIMATOR_DURATION_SCALE`；iOS 从 `UIAccessibility.isReduceMotionEnabled`；Windows 从 SystemParametersInfo `SPI_GETCLIENTAREAANIMATION`。

## 6. 边界情况

### 6.1 `queue_free` 冲突

用户调 `c.queue_free()` 时，Godot 走的是 `SceneTree` 的延迟删除队列。为了拦截需要区分三条路径：

| 路径 | 拦截可行性 | M 阶段 |
|---|---|---|
| 用户调 `container.remove_child(c)`（同步） | ✅ 直接在 `Container::remove_child` override 里拦 | **M2** |
| 用户调 `container.animate_remove(c)`（本提案新增显式 API） | ✅ 最稳，用户意图明确 | **M2** |
| 用户调 `c.queue_free()` / `c.free()`（异步 / 同步） | ⚠️ 复杂，详见下文 | **M2.5（降级策略）** |

**`queue_free` 路径的具体难点**：

1. `queue_free` 在当帧末由 `SceneTree` 批量调 `Node::_propagate_exit_tree` + `memdelete`。此时 `c.get_parent()` 仍然是 Container，但 Container 已经无法通过 signal 阻止流程
2. 监听 `SceneTree::node_removed`：该信号发出时节点已经 `_exit_tree`，再 `add_child` 回去需要额外处理信号重发、`_ready` 重跑等副作用
3. 阻止 `memdelete`：无法做到——`queue_free` 的契约是"必定被删"

**M2 默认策略（建议采纳）**：

1. **官方路径**：用户想要离场动画时，**必须**改调 `container.animate_remove(c)`，引擎保证动画播完后自动 `c.queue_free()`
2. **兜底策略**：若用户直接 `c.queue_free()`，Container 检测到子节点"即将离场但未经过 `animate_remove`"时：
   - **默认行为**：放行，节点立即消失（**无动画**），兄弟节点仍走 FLIP 位移。**不报错**，保持向后兼容
   - **可选严格模式**：`container.strict_exit_animation = true` 时打 warning，帮用户定位漏改的地方

3. `animate_remove` API 形态：
    ```gdscript
    # 播完 exit_preset 后自动 free
    container.animate_remove(child: Control) -> void

    # 播完 exit_preset 后调用自定义 callable（不 free）
    container.animate_remove(child: Control, on_done: Callable) -> void
    ```

**M2.5 可选增强（看社区反馈再做）**：通过 `SceneTree::node_removed` + 运行时把节点"克隆到临时 CanvasItem 上播完再丢"的 trick，支持 `queue_free` 路径也能自动播离场。代价是离场期间的节点不再是真节点（信号 / 绑定不可用），文档成本高。

**决策要点**：初版**宁可让"直接 queue_free 不播离场"成为明确契约**，也不做一套半吊子拦截。契约清楚的退化行为比"时灵时不灵"的魔法更可维护。

### 6.2 中途变更（interruption）

见 §5.2。核心要点：snapshot 基于"当前视觉位置"而非"上次动画起点"，Tween 被 kill 后立即重新 invert。FLIP 天然支持再入。

### 6.3 与 `VirtualBoxContainer` 的协作

VirtualBoxContainer 的子节点集合变化**有两种来源**：

| 触发 | 是否走 FLIP |
|---|---|
| 滚动导致的回收 / 入场 | **否**。纯粹是内部 bookkeeping，不是数据变化 |
| `notify_item_inserted` / `_removed` / `_moved` | **是**。这是真的拓扑变化 |
| `refresh()` / `refresh_item()` | **否**（refresh 是重绑，位置不变） |

VirtualBoxContainer 自己决定何时调用 Container 基类的 FLIP 逻辑，不依赖 `animate_layout_changes` 属性——或者说，它内部默认打开，但由逻辑而非属性触发。

### 6.4 与 DiffUtil 的协作

DiffUtil 的 `submit_list(new_keys)` 算出 insert / remove / move 序列后，逐条调用 `notify_*`，每条自然触发一次 FLIP。需要注意：

- 批量 diff 下，多条 `notify_*` 应该**合并**到同一次 `_sort_children`（通过 `queue_sort` 去重），一次性走 FLIP
- 否则每条变更都独立跑一次 snapshot/invert/play，视觉上会分裂

实现上：在 `notify_*` 里不立刻 `sort`，只打脏标记；下一帧统一 sort。这是 Godot 现有的 `queue_sort` 机制，天然支持。

### 6.5 锚点 / margin 变化

用户在动画期间改 `anchor_left` 或 `offset_*` 会触发 Container 重算→再次 FLIP。按 §6.2 的可中断性自然处理，但要注意**频率**：每帧改锚点会退化为每帧 FLIP，性能堪忧。实施中对 snapshot 做去抖（同一帧多次变更只 snapshot 一次）。

### 6.6 节点在动画中被重 parent

用户把 `c` 从 container A `reparent` 到 container B。当前行为：

- A 的 snapshot 里有 c 的 old_rect
- B 的 snapshot 里没有 c → 视为入场

所以 c 在 A 里离场、在 B 里入场，**不走"跨容器平滑飞过去"**。这是 L5 共享元素的范畴，本提案不处理。用户若想平滑跨容器，需用未来的 `hero_tag` 机制。

### 6.7 `visibility_changed`

子节点 `visible = false` 不会触发 `remove_child`，但会触发重新排版。约定：

- 默认：`visible = false` 按离场处理（走 exit 动画），`visible = true` 按入场
- 可通过 `container.animate_visibility_changes: bool = true`（单独开关，因不总是想要）控制

### 6.8 主题 `separation` 变化

`separation` 是 Container 的布局参数。运行时改动等价于"全部子节点可能都位移了"，走正常 FLIP 即可。

### 6.9 `VirtualGridContainer.columns` 运行时变化

等价于全量重排。子节点集合不变但位置全变 → 触发 L1 位移动画。用户体验上这是"换个排布方式"的合理动画表达。

## 7. 与现有系统的关系

| 系统 | 关系 |
|---|---|
| `Container` 基类 | **主要改动点**：新增属性 + `_sort_children` hook + 退场区 |

| `Theme` | `separation` 等主题项变化自然受益 |
| `DisplayServer` | 需新增 `is_reduce_motion_enabled()` 跨平台查询 |
| 路线图 §6.1 共享元素 / Hero | L5 场景，独立提案，**本提案的 FLIP 机制是其实现基础** |

## 9. 测试策略

### 9.1 单元测试（`tests/scene/test_container_transition.h`）

| 用例 | 要点 |
|---|---|
| 开关关闭 | 行为 100% 等同当前实现 |
| VBox 插入一个子节点 | 兄弟节点有 transform 过渡、新节点播入场预设 |
| VBox 删除一个子节点 | 被删节点进入退场区、兄弟节点过渡、动画后真 free |
| VBox 连续插入两条 | 中断重入正确，没有跳帧 |
| VBox 插删同时发生 | 批量合并到一次 FLIP |
| `queue_free` 路径（直调） | 降级契约：跳过离场动画、兄弟节点仍走 FLIP、无报错 |
| `animate_remove` 路径 | 拦截成功，节点不会在动画中途消失，完成后自动 free |
| `strict_exit_animation = true` 时 `queue_free` | 发 warning，不阻止流程 |
| `skip_next_layout_transition` | 下一次变更瞬切，之后恢复动画 |
| `reduce_motion` 模式 | 所有动画退化为瞬切，`queue_free` 立即生效 |
| VirtualBoxContainer 滚动 | **不**触发 FLIP |
| VirtualBoxContainer `notify_item_inserted` | 触发 FLIP |
| DiffUtil 批量 diff | 单次 FLIP 应用多条变更 |
| Stagger > 0 | 子节点按 index 错峰启动 |
| 主题 `separation` 运行时变化 | 全员位移动画 |
| 锚点 / offset 运行时变化 | 位移动画正确；去抖机制生效 |

### 9.2 性能基准

| 规模 | 目标 |
|---|---|
| 10 个子节点插删 | FLIP overhead < 0.2ms |
| 100 个子节点重排 | < 1.5ms |
| 1000 个子节点（VirtualBoxContainer 配合）| < 3ms（实际只对视口内的 ~20 个做 FLIP） |

监测指标：`Performance.TIME_PROCESS`、Tween 活跃数量、每帧 `NOTIFICATION_SORT_CHILDREN` 次数。

### 9.3 编辑器集成

- 属性检查器里 `animate_layout_changes` 默认收拢在 "Layout Transition" 组
- 选中后出现一个 "Preview transition" 按钮，临时加一个假子节点播一次入场 / 离场动画，帮助调参
- `ContainerTransition` 资源编辑器：可预览内置预设

## 10. 风险与未决

| 风险 | 缓解 |
|---|---|
| `queue_free` 拦截实现复杂 | M2 明确契约：`animate_remove` 是官方路径；直调 `queue_free` 退化为"跳过离场、保留兄弟 FLIP"。M2.5 再评估是否加克隆兜底 |
| 中断频繁时 Tween 数量爆炸 | 活跃 Tween 上限 + 到达后新变更直接瞬切 |
| 用户自写 Container（继承 Container 自定义 `_sort_children`）不兼容 | Pre-sort hook 设计成非侵入：只拍快照、不强制行为。自定义 Container 要想用这机制，把 `_sort_children` 放到 PRE/POST 通知之间即可 |
| `_layout_transition_offset` 新字段的引擎接受度 | 回退方案：在 `Container` 内部 HashMap 存 offset + 手动 push/pop `CanvasItem` transform（见 §3.1）。API 保持不变 |
| reduce motion 平台实现不一 | 每平台独立实现，缺失平台默认返回 false |
| 对非 Container 自定义布局失效 | 文档说明限制；后续可抽出 `LayoutAnimator` helper 让用户手动接入 |

未决：

- **是否默认开启？** 当前方案默认 `false`，零向后兼容风险；但也可考虑 "新建 Container 默认 true，加载旧 .tscn 保持 false"，由编辑器在 `.tscn` 里显式写出。倾向**默认 false + 编辑器新建节点时勾上**的折中方案
- **是否支持 CSS 风格的"按属性指定过渡"？** 如 `animate_opacity_duration = 0.3`、`animate_size_duration = 0.2`。初版不做，走预设路线；若社区提出再补
- **MotionLayout 风格的状态机过渡**是否纳入 M6+？ 量级大，建议独立提案
- **`Control` 非 Container 父子**的过渡（用户手动 `set_rect` 的布局）：不在本提案范围，未来可能抽 `LayoutAnimator` 节点作为 helper
