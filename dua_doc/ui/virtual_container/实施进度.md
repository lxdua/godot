### 1.4 待定设计话题

#### `item_min_size` 自动推导

**现状**：用户必须显式填 `item_min_size`；模板场景也含尺寸；两处定义容易漂移。

**反对"直接读模板"的技术原因**：
1. **时序问题**：`_compute_visible_range()` / `get_minimum_size()` 在任何 item 被 `instantiate()` 之前就要返回正确值——没法"按需测量"。
2. **副作用风险**：把探针节点放进 tree 会触发 `_ready`，用户模板里的 HTTP / Tween / Timer 也会触发。
3. **测量不在 tree 里可能偏小**：根节点 `custom_minimum_size` 不等于最终最小尺寸；真正的尺寸需要调 `get_combined_minimum_size()`，但未入 tree / 未解析主题时可能缺失依赖。

**方案对比**：

| 方案 | 描述 | 优点 | 缺点 |
|---|---|---|---|
| A. 探针 + 不入树 | `set_item_scene()` 时 `instantiate()` 一个探针，**不** `add_child`，直接读 `get_combined_minimum_size()`，然后 `queue_free` | 无 `_ready` 副作用 | 主题未解析，依赖主题的尺寸可能偏小 |
| B. 探针 + 入树 + 立即 remove | 同上但临时 `add_child`，测完 `remove_child` | 测量准确 | 模板 `_ready` 副作用会触发一次 |
| **C（推荐）. 保留 `item_min_size` 但作为"override"** | 默认用 A 自动测；用户显式填非零值则用用户的 | 兼容性最好，保留逃生口 | 两条路径，复杂度 +1 |
| D. 保留现状 + 改 doc | API 不变，文档里说清楚为什么要填 | 零改动 | 用户抱怨继续 |
| E. 第一帧 placeholder + 二次 resort | 第一次 sort 用占位值（如 1px），测完后再 `queue_sort` | 最准确 | 首帧闪烁、minimum_size two-pass |

**推荐**：C。`item_min_size` 默认 `Vector2(0, 0)` 意为"请自动推导"；用户填非零值时视为 override（继续当前语义）。实现要点：
- `_resolve_item_size()` 在 `item_scene` 设置时触发探针测量，结果缓存到 `measured_item_size`。
- 读取处 `_effective_item_size() = item_min_size != Vector2(0, 0) ? item_min_size : measured_item_size`。
- 探针路径选方案 A（不入 tree），文档里说明"若模板尺寸依赖主题，请显式填 `item_min_size`"。

**决策时机**：不在首次 PR 内做。首次 PR 的 API 契约是"用户必填 `item_min_size`"，改为 auto-derive 属于 API 增强，留到 item_min_size 使用量上来后再视反馈推进。

## 2. 文件与职责速览

### 2.1 `scene/gui/virtual_box_container.h`

核心声明。关键字段：

```cpp
class VirtualBoxContainer : public Container {
    Ref<PackedScene> item_scene;           // 模板场景
    int item_count = 0;                    // 逻辑总数
    bool vertical = true;                  // true=列表, false=横向
    Vector2 item_min_size = Vector2(0, 48);
    int buffer_items = 2;                  // 视口外预留缓冲
    int pool_size_limit = 32;              // 对象池容量上限

    struct ThemeCache { int separation = 4; } theme_cache;  // 由 BIND_THEME_ITEM 自动填充

    double scroll_offset = 0.0;            // 来自 Range API，保留 double
    HashMap<int, Control *> active_nodes;  // 索引 → 活跃节点
    LocalVector<Control *> pool;           // 回收池

    ScrollContainer *tracked_scroll_container = nullptr; // 沿父链找到的首个 SC
    bool in_sort_children = false;         // 再入保护

    enum ScrollAlign { ALIGN_VISIBLE, ALIGN_START, ALIGN_CENTER, ALIGN_END };
};
```

### 2.2 `scene/gui/virtual_box_container.cpp` 结构

从上到下按职责分段，每段有 `// =====` 标题：

1. **Internal helpers** - `_disconnect_tracked_scroll_container`、`_update_tracked_scroll_container`、`_on_scroll_changed`、`_on_viewport_resized`、`_item_stride`、`_content_main_size`、`_compute_visible_range`、`_acquire_node`、`_recycle_node`、`_release_all_nodes`、`_resort`
2. **Property accessors** - set/get × 6 个属性
3. **Data change notifications** - `refresh` / `refresh_item`
4. **Queries** - `get_bound_index` / `get_node_at_index` / `is_item_visible` / `get_first_visible_index` / `get_last_visible_index`
5. **Scrolling** - `scroll_to_index`（含 4 种对齐的 switch）
6. **Container overrides** - `get_minimum_size` / `_notification`
7. **Bindings** - `_bind_methods` 含所有 property / method / signal / enum / theme 绑定

关键实现点（下次 AI 千万别踩）：

- **主排序循环在 `_resort()`**：三阶段（evict → acquire+bind → position），用 `in_sort_children` 布尔保护防止 `add_child()` 触发的 `queue_sort` 递归。
- **`get_minimum_size()` 故意忽略子节点 min_size**：只用 `item_count * stride + cross`，保证滚动条范围稳定，不被回收节点闪动扰动。
- **`scroll_offset` 故意保留 `double`**：因为对接的是 `Range::get_value()`（Godot Range API 用 double）。`stride` / `main_size` / `main_pos` 等渲染布局量走 `real_t`。
- **轴切换时**：`set_vertical()` 会重新订阅对应轴的 scrollbar。用户需要同步调整 `item_min_size`（x↔y 互换），否则主轴尺寸为 0 会退化为"不显示任何节点"，这是**规范行为不是 bug**。
- **`add_child` 用 `INTERNAL_MODE_DISABLED`**：复用节点是普通子节点，用户 GDScript `get_children()` 能看到。这是之前讨论决定的（方案 B）。
